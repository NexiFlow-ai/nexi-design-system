What the suite looks and behaves like, in fourteen sentences. Every row below is already an owner decision somewhere in Epics 001…025; the register gathers them so a new screen, a new application or a model building one has a single page to obey.

## DS-0001 — Black · white · graphite, one accent

The surface is graphite text on warm white (Light) or layered graphite (Graphite); there is one accent (`--nexus-accent`) and it marks only what is selected, running or focused — never navigation chrome, never a chip. Colour is never the only carrier of meaning: a status is a dot *and* a label.

*Proof: <a href="/design-system/?path=/story/design-system-foundations--neutrals">design-system-foundations--neutrals</a>.*

## DS-0002 — Typography, spacing and borders over decorative colour

Hierarchy comes from size, weight and space. Borders separate; shadows are reserved for what floats. No gradients unless the product owner explicitly approves one; no illustration in product UI.

*Proof: <a href="/design-system/?path=/story/design-system-foundations--type">design-system-foundations--type</a>.*

## DS-0003 — One header line

A resource page in every app except NexCore and NexChat has one header line — back arrow · title · chips · Ask bar · icon actions · `⋯` — and the content starts right under it. No eyebrow, no lead, no mode tabs, no static explanatory sentence.

*Proof: <a href="/design-system/?path=/story/kit-pageframe--dense">kit-pageframe--dense</a>.*

## DS-0004 — A control that cannot change anything is not shown

A list that fits on one screen (12 rows at 1440 × 900) has no search, filter or view toggle; the row returns once the collection outgrows it and stays while a control is in use. A disabled control that can never be enabled is replaced by a sentence that says why (`Restriction`).

*Proof: <a href="/design-system/?path=/story/kit-forms--toolbar-row">kit-forms--toolbar-row</a>.*

## DS-0005 — Every read has its ladder

Every screen renders loading · empty · error · denied · offline · not found before its content, through the kit's `DataStateView`. Denied and not found look the same (the UI cannot tell "missing" from "not yours"); error and offline carry Retry; a spinner never sits over stale content.

*Proof: <a href="/design-system/?path=/story/kit-states--ladder">kit-states--ladder</a>.*

## DS-0006 — Honest copy, two languages, one card

Every string is a key (uk = en); copy never names a mechanism, never invents a value, and says the same thing for not-found and not-yours. One card, one progress, one receipt per action — the conversation register's honesty rules apply to every surface, not only to chat.

*Proof: <a href="/design-system/?path=/story/kit-states--errors">kit-states--errors</a>.*

## DS-0007 — Reversible asks inline, destructive asks by name

A reversible action confirms where it was taken — an inline `ActionPanel` that names the effect, one primary, Cancel. Only a destructive action (delete, revoke, archive with loss, remove a person) may take a modal, and it asks the person to type the name. Neither says "Are you sure?". A dirty form asks inline before discarding.

*Proof: <a href="/design-system/?path=/story/kit-editbar--confirmation">kit-editbar--confirmation</a>.*

## DS-0008 — Keyboard and screen reader first

Every interactive element has an accessible name; focus is visible (`:focus-visible`, 2 px); tabs, menus, switches, trees and separators use the WAI-ARIA pattern; the target is WCAG 2.2 AA and the workshop fails a story with a serious or critical axe violation.

*Proof: <a href="/design-system/?path=/story/kit-navigation--tabs">kit-navigation--tabs</a>.*

## DS-0009 — Adopt, do not re-implement

A screen composes the kit. A new idiom — a new chip, a new panel, a new table — goes through the register as a Design Change Request before code; a duplicate of a kit component in an app is a fitness failure.

*Proof: <a href="/design-system/?path=/story/kit-button--all-variants">kit-button--all-variants</a>.*

## DS-0010 — Tokens only

No raw colour, radius, shadow or font outside `packages/ui/src/tokens.css`. A screen that needs a new value proposes a token. Light and Graphite are one token contract; a component that hard-codes a colour breaks the Graphite audit.

*Proof: <a href="/design-system/?path=/story/design-system-foundations--neutrals">design-system-foundations--neutrals</a>.*

## DS-0011 — One shell, one launcher, one context

Every application mounts `NexusShell` with the shared App Launcher, header, organization · project context and Ask surface. An app does not invent its own navigation chrome, theme switch or locale switch.

*Proof: <a href="/design-system/?path=/story/design-system-foundations--layout">design-system-foundations--layout</a>.*

## DS-0012 — Motion is quiet

One shell transition (200 ms ease-out) and one progress pulse (600–900 ms); everything respects `prefers-reduced-motion`; nothing bounces, slides in from the edge or fades for decoration.

*Proof: <a href="/design-system/?path=/story/design-system-foundations--motion">design-system-foundations--motion</a>.*

## DS-0013 — Density is a contract, not a setting

`data-density="compact"` on `<html>` is the only way a screen gets denser; until the kit honours it the attribute is a no-op and no screen hand-rolls its own compact mode.

*Proof: <a href="/design-system/?path=/story/design-system-foundations--layout">design-system-foundations--layout</a>.*

## DS-0014 — Fixtures are synthetic

Every name, number, address and document in the workshop and the catalogue is invented; nothing is copied from a tenant, a customer or a real person. The publication scan fails on a secret or a real-looking identifier.

*Proof: <a href="/design-system/?path=/story/kit-datatable--populated">kit-datatable--populated</a>.*
