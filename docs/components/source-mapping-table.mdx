**DS-6707** · `apps/factory/src/components/parts/SourceMappingTable.tsx#SourceMappingTable` · proposed

Settings › Mapping: one row per canonical entity of the manufacturing family — the source's object beside it, the fields' count line (*9 of 9 mapped · 6 required*), the row's state **as a word** (*Mapped* · *Missing — required* · *Not available in this source* · *Proposed*; never colour alone, A11Y-2905) and the fields on demand (a disclosure per row: canonical · codec · the source's field). The version line says *Mapping v3 · approved 12 d ago by Ihor* or *proposed just now · not approved yet*; every row carries *Unverified* while the template is. *Discover* asks the source for its own description and proposes a version — a template, never a model; *Edit* wakes a text field per canonical field and a *Not available in this source* switch per field, plus the whole-set word for a set the source lacks; *Approve* writes the person's version or is refused with the rows still missing (`MAPPING_INCOMPLETE`, listed as the service names them). A reader sees a `Restriction`, never a disabled control. The only label on the screen is the connection's display name. Settings › Source beside it (`SourceHealthPanel`, same stories id family) carries the health line as a `role=status`, the checkpoints and *Check now* · *Sync now* · *Reconcile*. Not a kit duplicate: the kit's table has no notion of a canonical ↔ source row, a required field or an approval.
