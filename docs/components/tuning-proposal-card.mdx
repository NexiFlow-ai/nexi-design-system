The owner's one screen for a `tuning_proposal` approval: the Inbox card idiom with the tuner's best candidate against the baseline, opened from the Inbox as a *resource page*. Head: *Activate ⟨version⟩?* — the retrieval version going live, both when a processing dial changed too — the classification chip, the requester and the time (`chrome="page"` keeps the meta line only). Then, in this order: **Change** (`Facts` DS-3018: `⟨profile⟩ · ⟨dial⟩ old → new`, ≤ 12); **Goal** (`Facts`: *per-section fact coverage ≥ 0.60 · false evidence ≤ 5.0 %* and **met 11 / 14 sections**); **Overall** (`DataTable` DS-3030: metric · baseline · candidate · Δ — false evidence as a percentage, latencies in ms, the rest to two decimals; a Δ carries its sign and its tone); **Per section** (`DataTable`: section · baseline · candidate · Δ · state — **regressions first**, marked `◆ regression` in text, then met, then unmet — the contract's order, never re-sorted here). Foot: *Tried ⟨n⟩ candidates · best shown · all in the decision record · Open decision · Runs: baseline / candidate* (the two bench run pages of NexGraph, DS-6004, by their `dsv_…` id; the decision door is text until NexGraph's *Why* view lands), then *Decline* and *Approve*. A proposal the tuner marked `approvable = false` keeps *Approve* `aria-disabled` with the reason beside it (*guide/forge −0.03 regresses beyond 0.02*) — tasks-api refuses `approve` on it too, never UI-only. **Self-approval is allowed**: the requesting owner may approve their own tuner's proposal — the Flow and the model are what is gated, not the person; a non-decider reads it with the standard restriction sentence. Approve → the Flow activates as the approver and the line reads *Approved by you · ⟨time⟩ · rtp_default@2 is live*; Decline → *nothing changed — the draft stays a draft*. Numbers, ids and closed enums only: no question text, no page text.
