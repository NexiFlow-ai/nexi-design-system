**DS-5001** · `apps/chat/src/components/thread/TurnCard.tsx#TurnCard` · adopted

One component renders every executor — agent · knowledge · data · search · research · Flow · resolver · goal — from one contract. The header line is *‹title› · ‹who/what› · ‹elapsed or when›*, the title an executor's label and never an id. A plain answer is prose in the thread with no frame; work longer than the threshold shows **one** folded progress line that unfolds into the staged view and becomes the receipt with the result beneath it; a turn has at most one progress indicator. The eight states are closed, one copy class and one visual each; an unknown state renders `failed`, never blank. `waiting_on_you` carries the decision inline in the same idiom for every executor. Typography and borders only; no second colour. S8: the card has a `lead` slot — what it already holds about the ask, rendered first in every state, before the progress line and any wait; the goal fills it with its Situation strip (DS-5002), no other executor uses it yet.
