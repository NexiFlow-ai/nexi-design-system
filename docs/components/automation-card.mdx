**DS-5019** · `apps/chat/src/components/thread/AutomationCard.tsx#AutomationCard` · adopted

The one card an ask with `automation_intent` gets, for every role: *Set up an automation?* with four lines — what it will do · *When* (the schedule read back in words, with the zone) · *Using* (the connection or data, named, with its state) · *Tells* (the asker, in the bell and this chat — (a); *everyone in ⟨Project⟩* as an option) — and *Review setup · Not now*. *Review setup* is a disclosure: the schedule as a `Select` (daily · weekdays · weekly · custom under *Technical*), the time, the recipients, then *Not now · Confirm* (*Confirm and enable* for a builder). Then the card **is the summary** — its face a `role=status` chip line: *Draft — enable in Configure* · *Awaiting a builder* · *Enabled · next run ⟨when⟩* · *Paused* / *Paused — archived by ⟨name⟩* · *Needs changes — "⟨note⟩"* — with each run's receipt beneath (*07:02 · 3 changes · View*). Honesty: an unexpressible schedule asks for a time it can run and drafts nothing; a missing connection is named with its door and the face stays *Draft*; a missing template is said; **nothing runs until a human enables it**. Actions by role — builders *Pause · Change · Open in Configure*; members *Change · Stop asking*. Offline: *Confirm* `aria-disabled` with the reason.
