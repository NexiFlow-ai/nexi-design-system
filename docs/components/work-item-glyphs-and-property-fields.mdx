The atoms every VibeBan list, board card and Inspector row is built from. Priority (`‼ ! · ◦` + the word), stage (`○ ◔ ◑ ◕ ● ⊘`), type (epic · story · task · bug glyphs), blocked (`n` + direction), health (`StatusDot` with the word) — glyph + text, never colour alone. `ActorChip` is a human, an agent or a service with its kind; `DueLabel` says overdue · today · the date. The property fields are the Inspector's editors — bare at rest, framed on hover/focus (`quiet`), Enter commits, Esc reverts; `EstimateField` carries the project's unit. `ShowMore` is the page foot (*n of total · Show more*). **Typed item fields**: a type's `fields[]` (text · number · money · date · choice · yes/no · reference) are Inspector rows under the built-in ones in the same quiet idiom (`FieldRows` — money is a number and a 3-letter currency; a reference shows its prefix and takes the id; a `financial` row is absent for a viewer, *Not set* for an editor); the create form shows them as `Field`s (`FieldInputs`, required marked, a problem named at its row); a board card carries up to three `show_on_card` values as a label-less facts strip (`CardFacts`, the label is the title — DS-6105's *account · amount · closes*); a column head says each `rollup: sum` once after the count pill (`RollupLine`; *mixed* when the currencies disagree). Settings › Types edits a type's fields (`FieldSpecEditor`: label en · uk, kind, key locked once saved, required / at a stage category, on the card, sum, sensitivity, a choice's options one per line, a reference's prefix; ≤ 16) and reads them as one quiet line each (`FieldSpecList`). Built on `Chip` (DS-3003), `StatusDot` (DS-3004), `Field` (DS-3020), `Select`, `Switch`, `PropertyRow` and `Menu` (DS-3005); not a kit duplicate — the kit has no notion of a work item's priority, stage, type, estimate or typed field.
