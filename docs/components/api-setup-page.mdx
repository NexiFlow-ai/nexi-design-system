**DS-6902** · `apps/chat/src/components/builders/ToolSetup.tsx#ToolSetup` · adopted

*Connect a new API* as **the request's own resource page** under the Configure hub (amending (a): `/projects/{id}/tools/new` · `/projects/{id}/tools/{request_id}`, two lines of chrome — the hub's breadcrumb and one `BuilderHead` `← Tools · Connect a new API · Draft saved ⟨time⟩` — never a third `←`; the component is the body below that head): an ordered list of four sections that reveal in order — *Source* (an OpenAPI document by URL or file; the parse line *⟨title⟩ · ⟨host⟩ · N actions*; when an existing integration owns the host, a `RadioCard` pair with *Add actions to ⟨name⟩* as the default — never a duplicate by default) · *Actions* (two `fieldset`s of native checkboxes: *Reads data* ticked by default, *Makes changes* unticked with *Needs review*; a *Technical* disclosure per row) · *Connection* (**exactly one of three shapes, the preflight's answer** — DS-7019: *Use ⟨shared connection⟩* · *Add a key* (`SecretInput`, write-only, admins) · *Ask an administrator to connect it* (a note; never a key field); *Rights could not be read* shows no key field) · *Review* (`Facts`: API · hosts · actions · connection · next). A sticky footer *Save draft · Back · Continue / Send for review*; *Draft saved ⟨time⟩* polite. Refusals are plain words with the code under `details`, focus kept on the field. Not a kit duplicate: the kit's form inspector is one form; this is a stepped page whose third step is shaped by an authorization answer.
