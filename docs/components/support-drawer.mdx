**DS-5021** · `packages/ui/src/support/SupportDrawer.tsx#SupportDrawer` · proposed

The one place a signed-in person talks to NEXUS Platform Support from any screen: a right-rail drawer opened by the deterministic `+` row *Get NEXUS support* (every Ask surface, the NexChat composer, the shell's user menu) or by the door card *Ask NEXUS support →* after a dead-end turn. It hosts the provider installation's care widget frame (maxi) on the provider's origin — the suite shell passes **only** the signed support context (organization · opaque person ref · role class · language · ceiling), the text the person explicitly carried over, and `{app, label, kind}` of the screen; never the screen's data, the thread, a file or a URL with query text. Two tabs — *Conversation* (the frame; a `ScriptedDialogue` stands in for it in the workshop) · *My cases* (`SUP-n` · state · *expected reply by …* · the last public update). The drawer never shows a balance (038's page owns it) and never a staff full name. A Visitor never sees the row. Offline keeps the message and retries; a frame that cannot load says *Support is unavailable right now* with the Help & support link; a suspended organization's running session keeps the drawer. No mechanism word (*frame · assertion · PDP · grant row*) in copy; uk = en.
