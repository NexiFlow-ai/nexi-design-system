**DS-5024** · `apps/chat/src/components/thread/CapabilitySuggestionCard.tsx#CapabilitySuggestionCard` · proposed

The chat's answer when the Project has no tool for the ask. Under the answer's words: *Tools for this* and at most five rows, best first — a `ProviderMark` (DS-3066) · *Provider · Name* · the one act the projection's state word allows the person: *Add to ⟨agent⟩* (a builder; the turn's agent, the same bind the door makes) · *Connect ⟨provider⟩ →* (a `user_delegated` connection) · a reason chip and no button (*Needs an administrator* · *Not connected yet* · *Above this Project's classification*) — or the one line *Nothing here does that yet. You can connect a new API or ask an administrator.* Then the card's last door as an action row: *Connect a new API* (a builder → the S3 setup page with `?thread · message`; back returns to the thread, the request is filed under the turn) · *Ask an administrator*. The receipt is one `role=status` line (*Added to ⟨agent⟩.* · *Sent for review — the administrators of ⟨Project⟩ will see it.* · a refusal's line); the person's request's face follows beneath as a chip (*Awaiting review* · *Approved — added to ⟨agent⟩* · *Needs changes*) with *Open*. Honesty: a viewer gets the same rows with their reason and no act, no door; *nothing here* is byte-identical for an empty match and a match the person may not see; an `add` row the runtime's U6 card on the same turn already covers is not repeated; the sentence is nowhere in the card; the projection is the only source of rows. Offline: every act `disabled`, the words stay.
