## DS-1001 — Neutrals

Background, subtle, muted, surface, raised, text (primary · secondary · muted), border (default · strong), focus, and the one accent with its ring and soft tint. Both themes define every neutral; a component names the token, never the hex.

Tokens: `--nexus-bg … --nexus-accent-soft`

## DS-1002 — Semantic colour

Error, warning, success, info — four values, used sparingly, always with a label or an icon that carries the same meaning. They tint a chip's dot or an inline alert; they never fill a surface.

Tokens: `--nexus-error · --nexus-warning · --nexus-success · --nexus-info`

<Story id="design-system-foundations--semantic" height={520} />

## DS-1003 — Attention accents

Mint, pink, sky, amber, green, violet, slate, coral, copper, each with a soft tint. They identify an application in the launcher and may mark one running or selected thing on a screen. Never navigation chrome, never a chip, never text colour.

Tokens: `--nexus-accent-mint … --nexus-accent-copper-soft`

<Story id="design-system-foundations--accents" height={520} />

## DS-1004 — Per-application accents

Each application owns one accent pair (`--nexus-app-<app>-accent` · `-soft`) mapped to an attention accent. A new application claims a free pair in its UAT-0 and the scaffold writes it; two neighbours in the launcher never share a hue.

Tokens: `--nexus-app-chat-accent … --nexus-app-forge-soft`

<Story id="design-system-foundations--app-accents" height={520} />

## DS-1005 — Data palette

Eight categorical hues and one sequential ramp (`--nexus-data-1 … -8`, `--nexus-data-seq-1 … -5`) for things that are *data* — NexForge colour keys, NexBI series, NexMap layers, NexGraph hues — defined once in both themes with ≥ 3:1 against the surface. An app never picks its own chart colour; the attention accents (DS-1003) are not a data palette.

Tokens: `--nexus-data-1 … --nexus-data-seq-5 (new)`
